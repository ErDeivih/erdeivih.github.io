MuniPay

Las multas y los pagos del equipo, en una app con demo en vivo.

Ver repo ↗Demo en vivo ↗
  • Flutter
  • Dart
  • Firebase
  • Firestore

MuniPay nació porque en mi equipo de fútbol llevar las multas en un Excel era un caos. La app crea un equipo, cada jugador entra con un código de invitación, y desde ahí se registran multas, se controla quién debe y quién ha pagado, y se reparten los gastos comunes. Hay un dashboard con lo que va pasando por equipo y por jugador, y se pueden exportar reportes a Excel.

Está publicada y se puede probar: hay versión web (sin instalar) y APK para Android.

Lo que hace

  • Equipos con código de invitación y sus miembros.
  • Multas y sanciones por jugador.
  • Seguimiento de pagos y deudas.
  • Gastos compartidos del equipo.
  • Dashboard con estadísticas en tiempo real.
  • Exportación de reportes a Excel.
  • Dos roles: administrador y jugador.

Qué me llevé

El backend está montado entero con Firebase (Auth + Firestore), sin servidor propio, y la interfaz se actualiza en vivo suscribiéndose a los datos. Lo más interesante fue llevar ese modelo de “quién debe qué” a una pantalla que se entiende de un vistazo.

El problema de fondo

En un equipo hay varios flujos de dinero que se mezclan: multas por llegar tarde o por una tarjeta, gastos de material, y la caja común. Si cada uno lo apunta donde puede, al final nadie sabe cuánto debe ni quién ha pagado. MuniPay mete todo eso en un único sitio con dos roles claros.

Cómo está modelado

  • Equipo — el grupo. Se crea y se comparte con un código de invitación.
  • Miembro / jugador — cada persona del equipo, con su rol.
  • Multa — la registra el administrador contra un jugador.
  • Pago — la liquidación de una deuda (multa o gasto) por parte del jugador.
  • Gasto compartido — un coste que se reparte entre los miembros.

La parte que más me gustó

La relación entre deuda y pago: un jugador debe una cantidad, y la app agrega lo pendiente y lo pagado sin que la lógica se complique. Con eso, el dashboard y la exportación salen casi solos.

Stack

  • Flutter 3.35 (Dart) — una sola base de código para Android, iOS y web.
  • Firebase — Authentication y Cloud Firestore como backend.
  • Provider — gestión de estado.
  • Excel — exportación de reportes.

Cómo funciona por dentro

La interfaz se suscribe a Firestore, así que cuando cambia un dato en la base, la pantalla se actualiza sola. El estado se gestiona con Provider, y las colecciones guardan equipos, miembros, multas y pagos.

La parte de deuda/pago es sencilla: cada multa tiene un pagada/no pagada, y con eso se agrega el total pendiente por jugador.

class Deuda {
  final String jugadorId;
  final double importe;
  final bool pagada;
}

Decisiones que tomé

  • Reglas de Firestore para que cada rol solo vea y modifique lo suyo.
  • Multiplataforma desde un solo repo: web y APK se despliegan desde aquí.
  • Exportar a Excel para que los datos salgan de la app cuando hace falta.

Sin instalar nada

La versión web funciona en el navegador: Abrir MuniPay Web

Para Android, descarga el APK desde la última release, permitiendo instalar desde fuentes desconocidas.

Correrla en local

git clone https://github.com/ErDeivih/MuniPay.git
cd MuniPay
flutter pub get

Antes de arrancar hay que configurar Firebase (Auth + Firestore) y añadir el google-services.json. Las reglas de Firestore se despliegan con:

flutter run            # web o Android

Una vez dentro puedes: crear un equipo, añadir jugadores con su código de invitación, registrar una multa y ver cómo aparece en el dashboard. El backend es Firebase en su plan gratuito, así que no hay coste de servidor.
