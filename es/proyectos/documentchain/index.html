DocumentChain

Mi TFG: documentos con trazabilidad y control de acceso sobre una cadena de bloques.

Ver repo ↗
  • Solidity
  • Ethereum
  • IPFS
  • TypeScript
  • Docker

DocumentChain es mi Trabajo de Fin de Grado: un sistema de gestión documental que combina blockchain (Ethereum), IPFS y cifrado de extremo a extremo para guardar documentos de forma segura, con trazabilidad completa y control de acceso distribuido.

La idea es que la integridad del documento (quién lo subió, cuándo y qué versión) quede registrada en la cadena, mientras el contenido se almacena en IPFS y cifrado, de modo que el control no dependa de un único servidor. Todo se levanta con Docker Compose en Windows, Linux y macOS.

Qué incluye

  • Blockchain: contratos inteligentes en Ethereum (Solidity, Hardhat, Ethers.js) para trazabilidad y control de acceso.
  • Almacenamiento descentralizado: IPFS Cluster con varios nodos y replicación automática.
  • Cifrado end-to-end: AES-256-GCM para archivos y ECIES para compartir llaves.
  • Versionado: versiones de archivos on-chain.
  • Firmas digitales verificables y permisos a nivel de archivo.
  • Frontend en React 18 + TypeScript + Vite + Tailwind, y backend Node.js + Express.

Por qué me interesó

Era la primera vez que tocaba smart contracts y a la vez un proyecto con frontend, backend y despliegue con Docker. Me sirvió para cerrar el máster con algo que junta seguridad, criptografía y desarrollo web full-stack.

El problema

Guardar documentos importantes en un servidor normal tiene dos limitaciones: si el servidor cae o lo controlan, se pierde el control, y cuesta demostrar que un documento no se ha tocado. La solución que explora DocumentChain es repartir esa confianza: la cadena garantiza qué pasó y cuándo, e IPFS garantiza que el contenido sigue ahí, sin depender de una sola máquina.

Las tres piezas

  • Blockchain (Ethereum) — se usa como registro inmutable: quién subió cada documento, su versión y los permisos. Los contratos inteligentes hacen cumplir esas reglas por código, no por una persona.
  • IPFS Cluster — guarda el contenido real de los documentos, replicado en varios nodos con un balanceador delante, para que no dependa de un único servidor.
  • Cifrado end-to-end — el documento se cifra antes de subirse. AES-256-GCM para el archivo y ECIES para compartir las llaves con quien corresponda.

Qué aporta cada decisión

  • Trazabilidad: cada cambio deja huella on-chain y se puede verificar.
  • Control de acceso distribuido: los permisos viven en los contratos, no en una base de datos que alguien administra.
  • Integridad: al haber cifrado y registro en cadena, un documento no se puede alterar sin que se note.

Stack

  • Frontend: React 18 + TypeScript + Vite + TailwindCSS.
  • Backend: Node.js + Express, conectado a IPFS Cluster.
  • Blockchain: Solidity + Hardhat + Ethers.js.
  • Almacenamiento: IPFS Cluster (varios nodos con Nginx como balanceador).
  • Seguridad: AES-256-GCM + ECIES + MetaMask.
  • Despliegue: Docker Compose (Windows, Linux y macOS).

Cómo se conecta todo

Frontend ──► Backend API ──► Blockchain (Hardhat/ETH)
                 │
                 └──► IPFS Cluster (nodos + load balancer)

La petición pasa del frontend al backend, este registra la operación en la cadena y guarda el contenido en IPFS. El detalle que más trabajo me costó fue la limpieza automática de IPFS disparada por eventos de la blockchain.

Puertos cuando está arrancado

Servicio URL
Frontend http://localhost:5173
Backend API http://localhost:3000/api/health
Hardhat RPC http://localhost:8545

Requisitos

  • Docker Desktop
  • Git

Arrancarlo

git clone https://github.com/ErDeivih/DocumentChain.git
cd DocumentChain
docker compose up -d --build

La primera vez tarda ~5 minutos (descarga de imágenes y compilación). Los arranques siguientes son docker compose up -d (unos 30 segundos).

Usuarios de prueba

El backend genera automáticamente dos usuarios al iniciar:

Usuario Contraseña Rol
admin Admin1234 ADMIN
david David1234 USER

Probar los smart contracts

cd smart-contracts
npm install
npx hardhat test

Con esto verificas que los contratos de Ethereum se comportan como esperas. Para probar la app completa, entra en el frontend (http://localhost:5173), inicia sesión con los usuarios de arriba y prueba a subir un documento, ver su versión y compartir el acceso.
