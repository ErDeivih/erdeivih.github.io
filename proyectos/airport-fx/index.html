FX Aeropuertos

Estudiar cuánto efectivo de cada moneda necesita una oficina de aeropuerto.

  • Python

  • Análisis de demanda
Código en GitHub ↗

FX Aeropuertos es un proyecto de datos en preparación. Parte de una pregunta de una oficina de cambio: cuánto efectivo de cada moneda necesita para atender la demanda sin mantener más caja de la necesaria.

Qué quiero estudiar

La venta de divisa a viajeros reduce el stock; la compra de divisa lo repone y consume euros. El análisis previsto separa ambos movimientos para estudiar las necesidades de cada oficina.

Las fuentes

El diseño contempla tipos de cambio, turismo, pasajeros y calendarios de fuentes públicas. Como esos datos no incluyen operaciones individuales de cambio, el proyecto distingue información observada, estimaciones y transacciones simuladas.

Trabajo pendiente

Queda por completar la recogida de fuentes, construir el modelo de datos y preparar los informes. Después se podrán evaluar las previsiones y las decisiones de inventario con resultados medidos.

Disponibilidad

El repositorio recoge la base y el diseño del proyecto. Todavía no hay una aplicación, un panel público ni resultados de predicción publicados.

La idea clave

En preparación: fuentes y diseño definidos, con el análisis y el despliegue pendientes.

Fuentes previstas

El diseño contempla tipos de cambio, estadísticas de turismo y gasto, pasajeros por aeropuerto y calendarios. Se prevé conservar la procedencia y el periodo al que corresponde cada dato.

Información observada y estimada

Las fuentes públicas ofrecen datos agregados, pero no una relación completa entre país de origen, aeropuerto y operaciones de cambio.

El planteamiento estudia combinar esos agregados y estimar las relaciones que faltan. Las estimaciones se identificarán como tales, con sus supuestos.

Simulación y análisis

Las operaciones simuladas permitirían desarrollar el análisis sin utilizar transacciones empresariales reales. Después habría que comprobar que sus agregados encajan con las fuentes utilizadas.

Herramientas previstas

El diseño propone Python y DuckDB para trabajar con los datos, Dagster para la recogida y transformación, dbt para el modelo y Power BI para los informes. Estas piezas forman parte del plan; no se presenta el conjunto como terminado.

En preparación

El repositorio contiene la base del proyecto, la documentación de fuentes y el diseño del análisis. Todavía no hay un panel ni una aplicación publicados.

Siguientes pasos

  • Completar la recogida de datos de las fuentes seleccionadas.
  • Construir el modelo que permita relacionar turismo, pasajeros y monedas.
  • Preparar los informes y evaluar las previsiones con datos históricos.
  • Estudiar las decisiones de inventario a partir de esos resultados.

Código y documentación

El repositorio recoge el estado del trabajo y las instrucciones de desarrollo. Los resultados analíticos se añadirán cuando estén disponibles.
