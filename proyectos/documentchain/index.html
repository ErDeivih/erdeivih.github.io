DocumentChain

Guardar documentos cifrados y conservar un registro de sus versiones y permisos.

DocumentChain es mi Trabajo de Fin de Grado. Explora cómo gestionar documentos cifrados y mantener un registro de sus versiones, permisos y operaciones usando Ethereum e IPFS.

El recorrido de un documento

El archivo se cifra antes de almacenarse en IPFS. Los contratos de Ethereum registran la información de versiones y permisos, y una aplicación web permite consultar los documentos y trabajar con ellos.

El contenido y su registro se guardan en piezas distintas: el documento no se almacena dentro de la blockchain.

Qué incluye

  • Subida y consulta de documentos cifrados.
  • Versiones y trazabilidad de las operaciones.
  • Permisos para compartir acceso.
  • Almacenamiento en un clúster IPFS con varios nodos.
  • Interfaz web y un entorno de ejecución con Docker.

Decisiones del trabajo

El proyecto combina cifrado en el cliente, contratos en Solidity y almacenamiento distribuido. La coordinación entre estas piezas fue una parte importante del TFG, especialmente al actualizar o retirar contenido.

Disponibilidad

El trabajo académico está terminado. El repositorio contiene el código y las instrucciones para reproducir el entorno.

No tiene una aplicación pública desplegada. Utiliza una red de desarrollo y su alcance es el de un prototipo académico.

Las tres capturas de esta ficha son de esa ejecución local (14/11/2026): no hay demo pública ni imágenes de maqueta. El código que se ve es el del repositorio público.

Requisitos y dos formas de instalarlo

Ruta manual (la que se probó aquí): Node 20 o superior (probado con Node 24), PostgreSQL 16 y Git. El backend necesita una base de datos y un fichero .env con DATABASE_URL, los secretos JWT y el secreto de alta de administrador; el frontend es Vite y consume la API por /api.

Ruta Docker (la que documenta el repositorio): Docker Desktop y Git; docker compose up -d --build levanta base de datos, cadena local, backend y frontend. En esta máquina el build completo de Docker no terminó, por eso la ruta probada y documentada abajo es la manual.

El README del repositorio (github.com/ErDeivih/DocumentChain) es la referencia de instalación y requisitos exactos. El README menciona dos usuarios de prueba (admin/Admin1234 y david/David1234); en el arranque manual probado la base estaba vacía y la cuenta se creó desde el formulario de registro.

Cómo probarlo en local

El repositorio público trae la aplicación completa. Estos pasos son los que se probaron el 14/11/2026 para tomar las capturas (Node 24 y PostgreSQL 16; sirve Node 20 o superior):

  1. Base de datos: un PostgreSQL con una base documentchain y un usuario con permiso.
  2. Backend: cd backend && npm ci; copiar .env.example a .env y ajustar DATABASE_URL; npx prisma generate, npx prisma db push, npm run build, node dist/index.js (puerto 3000).
  3. Frontend: cd frontend && npm ci y node node_modules/vite/bin/vite.js --host 127.0.0.1 (puerto 5173, con proxy /api al backend).
  4. Abrir http://127.0.0.1:5173/ y crear una cuenta desde el registro.

También incluye docker compose para levantar todo junto; en esta máquina el build completo de Docker no terminó, así que la ruta probada y documentada es la de arriba. La instalación paso a paso con requisitos exactos vive en el README del repositorio.

Qué hace y qué no

Despliega una blockchain local para la demostración: sirve para estudiar el flujo de registro, versiones y permisos, pero no está preparada como servicio empresarial tal como está. La instalación y los requisitos exactos están en el README del repositorio.

Separar el documento de su registro

El TFG estudia cómo conservar documentos cifrados y registrar sus versiones y permisos mediante varias piezas que se coordinan entre sí.

El papel de cada pieza

  • Ethereum: registra versiones, permisos y operaciones mediante contratos.
  • IPFS Cluster: conserva el contenido cifrado y lo replica entre nodos.
  • Cifrado en el cliente: prepara el archivo antes de enviarlo y permite compartir las claves de acceso.

Integridad y disponibilidad

La referencia al contenido permite comprobar si corresponde al documento esperado. La disponibilidad depende de que los nodos que conservan ese contenido sigan operativos; el uso de IPFS por sí solo no garantiza su conservación.

El trabajo se desarrolla sobre una red de prueba. Su alcance y sus limitaciones están documentados en el repositorio.

Interfaz y coordinación

React y TypeScript forman la interfaz web. Una API en Node.js y Express coordina las operaciones con el almacenamiento y los contratos.

Documentos y versiones

Los contratos están escritos en Solidity. El contenido se almacena en IPFS Cluster con varios nodos y Nginx como balanceador.

El cifrado del archivo utiliza AES-256-GCM y el intercambio de claves utiliza ECIES. El documento cifrado y el registro de su versión se gestionan por separado.

Entorno del proyecto

Docker Compose reúne las piezas del prototipo, incluida la red de desarrollo. La documentación del repositorio describe la arquitectura y cómo reproducirla.

Un prototipo académico

DocumentChain es un trabajo de investigación y desarrollo, no un servicio público de almacenamiento. El código y la documentación están disponibles en GitHub.

Qué se puede explorar

El entorno del proyecto permite recorrer la subida de un documento, consultar su versión y gestionar permisos de acceso. Incluye la aplicación web y las piezas de almacenamiento y registro que la acompañan.

Reproducir el trabajo

El repositorio explica cómo preparar el entorno con Docker y una red de desarrollo. Las instrucciones de instalación y los datos de ejemplo se mantienen allí para acompañar a la versión del código.
