MuniPay was not built to showcase Flutter. It started because my football team tracked fines,
payments and expenses in a spreadsheet that did a poor job of explaining who owed what.

I turned that routine into a product with two clear roles. The administrator creates the team,
records fines and tracks payments; each player joins with an invite code and sees their own position.
The same codebase ships on the **web** and as an **Android APK**.

## What it solves today

- Teams and members connected by invite code.
- Fines, penalties, payments and shared expenses.
- A live summary for each team and player.
- Excel exports so the data is not trapped inside the app.
- Separate admin and player access through Firebase Authentication and Firestore rules.

## The decision behind the project

There is no custom server. The UI subscribes to Firestore and derives debts, payments and totals
from those records. That kept infrastructure light, but also made **security rules** and collection
design a central part of the architecture.

## Honest status

The web build is live and the repository offers an Android release. It remains under development:
some technical documentation needs cleanup and local setup requires your own Firebase project.
