DocumentChain es mi Trabajo de Fin de Grado. Explora cómo gestionar documentos cifrados y mantener un registro de sus versiones, permisos y operaciones usando Ethereum e IPFS.

## El recorrido de un documento

El archivo se cifra antes de almacenarse en IPFS. Los contratos de Ethereum registran la información de versiones y permisos, y una aplicación web permite consultar los documentos y trabajar con ellos.

El contenido y su registro se guardan en piezas distintas: el documento no se almacena dentro de la blockchain.

## Qué incluye

- Subida y consulta de documentos cifrados.
- Versiones y trazabilidad de las operaciones.
- Permisos para compartir acceso.
- Almacenamiento en un clúster IPFS con varios nodos.
- Interfaz web y un entorno de ejecución con Docker.

## Decisiones del trabajo

El proyecto combina cifrado en el cliente, contratos en Solidity y almacenamiento distribuido. La coordinación entre estas piezas fue una parte importante del TFG, especialmente al actualizar o retirar contenido.

## Requisitos y dos formas de instalarlo

**Ruta manual (la que se probó aquí):** Node 20 o superior (probado con Node 24), PostgreSQL 16 y Git.
El backend necesita una base de datos y un fichero `.env` con `DATABASE_URL`, los secretos JWT y el
secreto de alta de administrador; el frontend es Vite y consume la API por `/api`.

**Ruta Docker (la que documenta el repositorio):** Docker Desktop y Git; `docker compose up -d
--build` levanta base de datos, cadena local, backend y frontend. En esta máquina el build completo de
Docker no terminó, por eso la ruta probada y documentada abajo es la manual.

El **README del repositorio** ([github.com/ErDeivih/DocumentChain](https://github.com/ErDeivih/DocumentChain#readme))
es la referencia de instalación y requisitos exactos. El README menciona dos usuarios de prueba
(`admin`/`Admin1234` y `david`/`David1234`); en el arranque manual probado la base estaba vacía y la
cuenta se creó desde el formulario de registro.

## Cómo probarlo en local

El repositorio público trae la aplicación completa. Estos pasos son los que se probaron el
14/11/2026 para tomar las capturas (Node 24 y PostgreSQL 16; sirve Node 20 o superior):

1. **Base de datos**: un PostgreSQL con una base `documentchain` y un usuario con permiso.
2. **Backend**: `cd backend && npm ci`; copiar `.env.example` a `.env` y ajustar `DATABASE_URL`;
   `npx prisma generate`, `npx prisma db push`, `npm run build`, `node dist/index.js` (puerto 3000).
3. **Frontend**: `cd frontend && npm ci` y `node node_modules/vite/bin/vite.js --host 127.0.0.1`
   (puerto 5173, con proxy `/api` al backend).
4. Abrir `http://127.0.0.1:5173/` y crear una cuenta desde el registro.

También incluye `docker compose` para levantar todo junto; en esta máquina el build completo de
Docker no terminó, así que la ruta probada y documentada es la de arriba. La instalación paso a paso
con requisitos exactos vive en el README del repositorio.

## Qué hace y qué no

Despliega una **blockchain local** para la demostración: sirve para estudiar el flujo de registro, versiones y permisos, pero no está preparada como servicio empresarial tal como está. La instalación y los requisitos exactos están en el README del repositorio.
