DocumentChain es mi **Trabajo de Fin de Grado**. La pregunta de partida era concreta: ¿cómo se puede
demostrar quién hizo qué con un documento sin entregar todo el control a un único servidor?

La respuesta del proyecto reparte responsabilidades. El contenido se cifra en el cliente y se guarda
en un clúster IPFS; los contratos de Ethereum registran versiones, permisos y operaciones; un backend
coordina ambos mundos y la interfaz permite trabajar con ellos sin exponer esa complejidad.

## Qué construí

- Contratos en Solidity para trazabilidad, versionado y permisos por archivo.
- Cifrado AES-256-GCM del contenido y ECIES para compartir claves.
- IPFS Cluster con tres nodos, replicación y balanceo mediante Nginx.
- Frontend React + TypeScript y API Node.js + Express.
- Entorno reproducible con Docker Compose y pruebas de contratos con Hardhat.

## La parte difícil

No era “subir un PDF a blockchain”: eso sería caro y poco práctico. El trabajo estuvo en coordinar
tres fuentes de verdad con fallos distintos y mantener una referencia verificable entre el hash,
la versión registrada y el contenido cifrado. También implementé limpieza de IPFS dirigida por eventos
de los contratos.

## Hasta dónde llega

Es un prototipo académico completo para ejecución local. Usa una red Hardhat de desarrollo y no debe
confundirse con un servicio auditado o preparado para mainnet. Esa frontera está documentada en el repositorio.
