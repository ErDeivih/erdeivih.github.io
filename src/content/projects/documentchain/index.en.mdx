DocumentChain is my **final degree project**. It began with a concrete question: how can you prove
who did what with a document without giving a single server complete control?

The project splits that responsibility. Content is encrypted in the browser and stored in an IPFS
cluster; Ethereum contracts record versions, permissions and operations; a backend coordinates both
sides, while the interface keeps that complexity out of the user's way.

## What I built

- Solidity contracts for traceability, versioning and file-level permissions.
- AES-256-GCM content encryption and ECIES key sharing.
- A three-node IPFS Cluster with replication and Nginx load balancing.
- A React + TypeScript frontend and Node.js + Express API.
- A reproducible Docker Compose environment and Hardhat contract tests.

## The hard part

This was not “put a PDF on the blockchain”—that would be expensive and impractical. The challenge
was coordinating three sources of truth with different failure modes while keeping a verifiable link
between the hash, recorded version and encrypted content. I also implemented event-driven IPFS cleanup.

## Where it stops

This is a complete academic prototype for local execution. It uses a local Hardhat network and should
not be mistaken for an audited, mainnet-ready service. That boundary is documented in the repository.
