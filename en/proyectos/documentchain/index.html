DocumentChain

My final project: documents with traceability and access control on a blockchain.

View repo ↗
  • Solidity
  • Ethereum
  • IPFS
  • TypeScript
  • Docker

DocumentChain is my final degree project: a document management system that combines blockchain (Ethereum), IPFS and end-to-end encryption to store documents securely, with full traceability and distributed access control.

The idea is that the document’s integrity (who uploaded it, when and which version) stays on the chain, while the content is stored in IPFS and encrypted, so control doesn’t depend on a single server. Everything runs with Docker Compose on Windows, Linux and macOS.

What it includes

  • Blockchain: smart contracts on Ethereum (Solidity, Hardhat, Ethers.js) for traceability and access control.
  • Decentralized storage: IPFS Cluster with several nodes and automatic replication.
  • End-to-end encryption: AES-256-GCM for files and ECIES to share keys.
  • Versioning: on-chain file versions.
  • Digital signatures that are verifiable and per-file permissions.
  • Frontend in React 18 + TypeScript + Vite + Tailwind, and backend Node.js + Express.

Why it caught my interest

It was the first time I touched smart contracts and, at the same time, a project with frontend, backend and Docker deployment. It let me close the degree with something that combines security, cryptography and full-stack web development.

The problem

Storing important documents on a plain server has two limits: if the server goes down or is taken over, you lose control, and it’s hard to prove a document hasn’t been touched. The solution DocumentChain explores is to spread that trust: the chain guarantees what happened and when, and IPFS guarantees the content is still there, without depending on a single machine.

The three pieces

  • Blockchain (Ethereum) — used as an immutable ledger: who uploaded each document, its version and the permissions. Smart contracts enforce those rules in code, not by a person.
  • IPFS Cluster — holds the actual document content, replicated across several nodes behind a load balancer, so it doesn’t rely on one server.
  • End-to-end encryption — the document is encrypted before being uploaded. AES-256-GCM for the file and ECIES to share the keys with whoever should have access.

What each decision adds

  • Traceability: every change leaves an on-chain trace that can be verified.
  • Distributed access control: permissions live in the contracts, not in a database someone manages.
  • Integrity: with encryption and an on-chain record, a document can’t be altered without being noticed.

Stack

  • Frontend: React 18 + TypeScript + Vite + TailwindCSS.
  • Backend: Node.js + Express, connected to IPFS Cluster.
  • Blockchain: Solidity + Hardhat + Ethers.js.
  • Storage: IPFS Cluster (several nodes with Nginx as load balancer).
  • Security: AES-256-GCM + ECIES + MetaMask.
  • Deployment: Docker Compose (Windows, Linux and macOS).

How it all connects

Frontend ──► Backend API ──► Blockchain (Hardhat/ETH)
                 │
                 └──► IPFS Cluster (nodes + load balancer)

The request goes from the frontend to the backend, which registers the operation on the chain and stores the content in IPFS. The bit that cost me the most work was the automatic IPFS cleanup triggered by blockchain events.

Ports once it’s running

Service URL
Frontend http://localhost:5173
Backend API http://localhost:3000/api/health
Hardhat RPC http://localhost:8545

Requirements

  • Docker Desktop
  • Git

Boot it up

git clone https://github.com/ErDeivih/DocumentChain.git
cd DocumentChain
docker compose up -d --build

The first time takes ~5 minutes (image downloads and compilation). Subsequent starts are docker compose up -d (about 30 seconds).

Test users

The backend generates two users automatically on start:

User Password Role
admin Admin1234 ADMIN
david David1234 USER

Test the smart contracts

cd smart-contracts
npm install
npx hardhat test

This checks that the Ethereum contracts behave as expected. To test the whole app, open the frontend (http://localhost:5173), log in with the users above and try uploading a document, seeing its version and sharing access.
