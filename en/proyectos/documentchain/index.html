DocumentChain is my final degree project. It explores managing encrypted documents and recording versions, permissions and operations using Ethereum and IPFS.

A document’s journey

Files are encrypted before being stored in IPFS. Ethereum contracts record version and permission information, while a web application lets users view and manage documents.

Content and its record are stored separately: the document itself does not live on the blockchain.

What it includes

  • Uploading and viewing encrypted documents.
  • Versions and operation history.
  • Permissions for sharing access.
  • Storage in an IPFS cluster with multiple nodes.
  • A web interface and a Docker execution environment.

Project decisions

The project combines client-side encryption, Solidity contracts and distributed storage. Coordinating these pieces was an important part of the work, especially when updating or removing content.

Availability

The academic project is complete. The repository contains the code and instructions to reproduce its environment.

There is no deployed public application. It uses a development network and remains an academic prototype.

The three screenshots in this entry come from that local run (14/11/2026): there is no public demo and no mock-up imagery. The code shown is the public repository’s code.

Requirements and two ways to install it

Manual route (the one tested here): Node 20 or later (tested with Node 24), PostgreSQL 16 and Git. The backend needs a database and a .env file with DATABASE_URL, the JWT secrets and the admin bootstrap secret; the frontend is Vite and consumes the API through /api.

Docker route (documented by the repository): Docker Desktop and Git; docker compose up -d --build starts the database, local chain, backend and frontend. On this machine the full Docker build did not finish, which is why the tested and documented route below is the manual one.

The repository README (github.com/ErDeivih/DocumentChain) is the reference for exact installation and requirements. The README mentions two test users (admin/Admin1234 and david/David1234); in the manual run tested here the database was empty and the account was created from the registration form.

How to try it locally

The public repository contains the full application. These are the steps tested on 14/11/2026 to take the screenshots (Node 24 and PostgreSQL 16; Node 20 or later works):

  1. Database: a PostgreSQL instance with a documentchain database and a user with permissions.
  2. Backend: cd backend && npm ci; copy .env.example to .env and adjust DATABASE_URL; npx prisma generate, npx prisma db push, npm run build, node dist/index.js (port 3000).
  3. Frontend: cd frontend && npm ci and node node_modules/vite/bin/vite.js --host 127.0.0.1 (port 5173, proxying /api to the backend).
  4. Open http://127.0.0.1:5173/ and create an account from the registration form.

It also ships a docker compose setup to run everything together; on this machine the full Docker build did not finish, so the tested and documented path is the one above. Exact step-by-step installation and requirements live in the repository README.

What it does and what it does not

It runs a local blockchain for the demo: it is useful to study the registry, versioning and permissions flow, but it is not ready as an enterprise service as it stands. Exact installation steps and requirements are in the repository README.

Fact

A completed academic prototype, with code and documentation on GitHub.

Separate documents from their records

The degree project explores keeping encrypted documents and recording versions and permissions through coordinated components.

Each component’s role

  • Ethereum: contracts record versions, permissions and operations.
  • IPFS Cluster: stores encrypted content and replicates it between nodes.
  • Client-side encryption: prepares files before sending them and supports sharing access keys.

Integrity and availability

The content reference allows checking whether it matches the expected document. Availability depends on the nodes storing that content remaining operational; IPFS alone does not guarantee retention.

The project uses a development network. Its scope and limitations are documented in the repository.

Interface and coordination

React and TypeScript form the web interface. A Node.js and Express API coordinates storage and contract operations.

Documents and versions

Contracts are written in Solidity. Content is stored in an IPFS cluster with multiple nodes and Nginx for load balancing.

Files use AES-256-GCM encryption and keys are shared with ECIES. Encrypted content and version records are managed separately.

Project environment

Docker Compose brings the prototype’s components together, including its development network. The repository documents the architecture and how to reproduce it.

An academic prototype

DocumentChain is a research and development project, not a public storage service. Code and documentation are available on GitHub.

What can be explored

The project environment supports uploading a document, viewing its version and managing access permissions. It includes the web application and its storage and record components.

Reproduce the project

The repository explains how to prepare the environment with Docker and a development network. Installation instructions and sample data are kept there alongside the code version.

There is no deployed public demo yet.
