Airport FX

FX Aeropuertos is a data project in preparation. It starts with an exchange office’s question: how much cash in each currency is needed to meet demand without keeping unnecessary stock?

What I want to study

Selling currency reduces stock; buying it replenishes stock and consumes euros. The planned analysis separates these flows to study each office’s requirements.

Sources

The design considers public exchange rates, tourism, passenger figures and calendars. These sources do not include individual exchange transactions, so the project separates observed information, estimates and simulated transactions.

Remaining work

Source collection, the data model and reports still need to be completed. Forecasts and inventory decisions can then be evaluated using measured results.

Availability

The repository contains the project’s starting point and design. There is no published application, public dashboard or forecasting result yet.

The key idea

In preparation: sources and design are defined; analysis and deployment remain pending.

Planned sources

The design considers exchange rates, tourism and spending statistics, airport passenger figures and calendars. Each data point is intended to retain its source and reporting period.

Observed and estimated information

Public sources provide aggregate data, but not a complete relationship between origin country, airport and currency exchange transactions.

The approach explores combining aggregates and estimating missing relationships. Estimates will be identified with their assumptions.

Simulation and analysis

Simulated transactions would support analysis without using real business transactions. Their aggregates would then need to be checked against the source data.

Planned tools

The design proposes Python and DuckDB for data work, Dagster for collection and transformation, dbt for the model and Power BI for reports. These components are planned; the combined system is not presented as finished.

In preparation

The repository contains the project’s starting point, source documentation and analysis design. There is no published dashboard or application yet.

Next steps

  • Complete collection from selected sources.
  • Build a model relating tourism, passengers and currencies.
  • Prepare reports and evaluate forecasts against historical data.
  • Study inventory decisions using those results.

Code and documentation

The repository records progress and development instructions. Analytical results will be added when available.
