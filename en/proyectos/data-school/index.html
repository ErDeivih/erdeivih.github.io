Data School

A data and AI portal where every published figure has executed code and a test behind it.

Fact:459 sheets with executed code and a learning index with prerequisites.

Data School has two parts: a study and practice portal for data and AI, and the ordered catalogue of the content that feeds it. The rule is the same in both: nothing goes in without executed code, a licence and a test that backs it up.

What it is, what it is for and what I built

What it is. A data and AI portal with study sheets, licensed datasets and the code behind every figure so it can be reproduced.

What it is for. To study data with verifiable material: every published number has the code that produces it and the dataset source underneath.

What I built. The catalogue and its content pipeline, the datasets and their quality sheets, search, the PWA and the automated checks that validate the manifest, links and nulls.

What I did not do. It is not a platform with accounts and it does not issue certificates. Some content is still pending and dark mode is a work in progress.

The problem

Learning data and AI is easy to start and hard to prove: courses stay in videos and projects stay in notebooks nobody can open. The material itself was spread across five different origins, with duplicated content and no shared rule for licences, data or tests.

Approach

  • Publishes a portal with 459 sheets, downloadable packages with their own verifier and a learning index with hours and prerequisites; search handles synonyms.
  • Orders the catalogue: 32 checked sources with licence, cost, language and status; 15 only allow a link and our own summary, so they are not copied.
  • Publishes its own data: 10 synthetic datasets under CC0-1.0, with SHA-256 checksum, a fixed-seed generator and a quality profile.
  • Checks: a link checker with a weekly task and decision documents (ESPECIFICACION.md, DECISIONES.md, DOCTRINA-CALIDAD.md) recording what enters and what is dropped.

Data and data model

  • Portal model: sheets ↔ phases ↔ routes ↔ prerequisites; projects with a package, rubric and milestones; packages with verified bytes and sha256.
  • 13 phases (f00–f12), from mathematical foundations to communication and career. Each sheet carries frontmatter with id, titulo, fase, nivel, rutas, prerequisitos, tags, resumen and fuentes.
  • Figures with provenance: 350 Python scripts generate 370 SVGs and each figure points to its source.
  • Entry rule: every concept with executed code; every dataset with a licence and provenance.
  • Automated gates: checks for usability, spacing, library, downloads and offline use; ZIP validation against the manifest.
  • Data quality: 10/10 CSVs load, 63/63 columns and types correct, 0 nulls and 0 duplicates; 82 links checked (79 live, 3 redirect, 0 dead).

What I learned building it

  • Data models and Data Marts: the sheet–phase–route–prerequisite relationship, packages with sha256 and datasets with a sheet and a quality profile.
  • ETL: Markdown and YAML turned into semantic HTML, a search index, a glossary, datasets and an offline manifest.
  • KPIs and coverage: coverage measured per phase and per dataset, with a count of checks in every automated gate.
  • Quality and debugging: ZIP validation against the manifest, 0 nulls and 0 duplicates in the CSVs, a link checker and a documented correction of a wrong figure (the “link-only” sources are 15, not 11).

Real state

Done and verifiable: portal published on GitHub Pages with the index, search and downloadable packages; catalogue consolidated and measured from five origins; automated gates green. No GitHub Actions: everything runs locally.

Pending: 9 legal fields for the site owner that the portal itself marks as missing, a dark theme in progress, ten project sheets still to complete and a real usage metric (downloads and sessions) to turn coverage into impact.
