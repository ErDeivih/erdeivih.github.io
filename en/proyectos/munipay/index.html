MuniPay

Team fines and payments, in an app with a live demo.

View repo ↗Live demo ↗
  • Flutter
  • Dart
  • Firebase
  • Firestore

MuniPay started because keeping track of fines in my football team with a spreadsheet was a mess. The app creates a team, each player joins with an invite code, and from there you record fines, track who owes and who has paid, and split shared expenses. There’s a dashboard with what’s happening per team and per player, and you can export reports to Excel.

It’s published and you can try it: there’s a web version (no install) and an Android APK.

What it does

  • Teams with an invite code and their members.
  • Fines and penalties per player.
  • Payment and debt tracking.
  • Shared team expenses.
  • Dashboard with real-time stats.
  • Export reports to Excel.
  • Two roles: admin and player.

What I took from it

The whole backend is Firebase (Auth + Firestore), no own server, and the UI updates live by subscribing to the data. The most interesting part was turning that “who owes what” model into a screen you understand at a glance.

The underlying problem

A team has several money flows mixed together: fines for being late or for a card, material expenses, and the shared pot. If everyone writes it down wherever, in the end nobody knows how much is owed or who has paid. MuniPay puts all of that in one place with two clear roles.

How it’s modelled

  • Team — the group. Created and shared with an invite code.
  • Member / player — each person in the team, with their role.
  • Fine — recorded by the admin against a player.
  • Payment — settling a debt (fine or expense) by a player.
  • Shared expense — a cost split among members.

The part I liked most

The relationship between debt and payment: a player owes an amount, and the app aggregates what’s pending and what’s paid without the logic getting complicated. With that, the dashboard and the export almost come out on their own.

Stack

  • Flutter 3.35 (Dart) — one codebase for Android, iOS and web.
  • Firebase — Authentication and Cloud Firestore as the backend.
  • Provider — state management.
  • Excel — report export.

How it works inside

The UI subscribes to Firestore, so when a value changes in the database, the screen updates by itself. State is managed with Provider, and the collections hold teams, members, fines and payments.

The debt/payment part is simple: each fine has a paid/unpaid flag, and from that you aggregate the pending total per player.

class Deuda {
  final String jugadorId;
  final double importe;
  final bool pagada;
}

Decisions I made

  • Firestore rules so each role only sees and modifies its own stuff.
  • Multi-platform from a single repo: web and APK are deployed from here.
  • Export to Excel so the data can leave the app when needed.

Without installing anything

The web version runs in the browser: Open MuniPay Web

For Android, download the APK from the latest release, allowing installs from unknown sources.

Run it locally

git clone https://github.com/ErDeivih/MuniPay.git
cd MuniPay
flutter pub get

Before starting you need to set up Firebase (Auth + Firestore) and add the google-services.json. Firestore rules are deployed with:

flutter run            # web or Android

Once inside you can create a team, add players with their invite code, log a fine and see it appear on the dashboard. The backend is Firebase on the free plan, so there’s no server cost.
