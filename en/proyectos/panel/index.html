The panel gathers every ongoing project on one page and answers a very concrete question: what can I open right now, and what is actually up?

The problem

Each project lives in its own folder, with its status noted in a different file, and it is easy to present as “published” something that stopped responding days ago. Before opening each demo you had to remember which one was deployed, which one only ran locally and when it was last checked.

What it does

  • Lists every project with its category, its status (up, down or expired) and the time of the last check.
  • Separates what can be opened (9) from the total (17): it does not mix projects with a public demo with those without.
  • The status expires: if it has not been checked again within the window, it stops being shown as current.
  • Links each project to its demo or page and keeps the checking rhythm on a separate page.

Data and data model

estados.json keeps each project’s checked status with its timestamp and expiry; ritmo.json keeps the history of checks. The HTML is generated statically: there is no server or database that can lie on its own; if the data is missing, the project shows as unchecked.

What it shows for a Business Analyst role

  • A small, useful dashboard: one headline figure (openable), its base (total) and the reason a row stops being valid.
  • Data quality: status expires and “unchecked” is different from “down”.
  • Simple explicit model: two JSON files with date and expiry, consumed by a static page.

Real status

Done and verifiable: the panel is published with the full list, category filters and the checking rhythm. The latest check shown in the demo is 14/11/2026.

Pending: warn when a project has been down for several checks in a row, and add a longer-term history view.
